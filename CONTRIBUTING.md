# Contributing

Thanks for helping. The harness is small on purpose: every rule costs context in every session, and
every hook pattern is a chance for a false block. A change is welcome when it fixes a measured
problem with the smallest addition that fixes it.

## Before you open a pull request

```bash
python3 -B -m unittest discover -s agent-core/tests      # must pass, no new skips
python3 agent-core/scripts/sync_agent_config.py          # after editing AGENTS.md or a skill
python3 agent-core/scripts/check_agent_config.py
python3 agent-core/scripts/upgrade_harness.py --write-manifest
```

## What each kind of change needs

| Change | Needs |
|---|---|
| New blocked command or secret file (`agent-core/hooks/policy.py`) | A test for the block **and** a test that a similar everyday command is still allowed. Say which provider/version you saw the gap on. |
| Hook adapter behaviour | A real run: `provider_smoke.py` for that provider (or `codex_hook_probe.py` for Codex), with the CLI version in the PR. |
| `AGENTS.md` | Keep it under 150 nonblank lines (the config check enforces it). Explain what agents did wrong without the change. |
| A skill or its description | Run `run_evals.py` for at least one provider before and after; include both scores. Add an eval case if none covers the behaviour. |
| Claude settings (`.claude/settings.json`) | Explain the measured behaviour on the Claude Code version you used; sandbox and permission semantics change between versions. |

Edit canonical files only: root `AGENTS.md` and `.agents/skills/`. `.agents/AGENTS.md` and
`.claude/skills/` are generated by `sync_agent_config.py`.

## Style

Python 3.10+, standard library only, no new dependencies. Short functions, no speculative options.
Scripts never print secret values and never change user-level settings.

## Changelog

Add a line to `CHANGELOG.md` under the next version.
